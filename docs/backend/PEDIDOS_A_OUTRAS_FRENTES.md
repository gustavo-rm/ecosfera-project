# Pedidos a outras frentes

O `platform-api` não altera pacotes de outras frentes. O que precisa mudar fora dele fica aqui.

| # | Frente | Pedido | Por quê | Estado |
|---|---|---|---|---|
| P1 | Infra (`infra/compose/dev.yml`) | Trocar `minio/minio:latest` e `minio/mc:latest` por imagem disponível (ex.: `chainguard/minio`) ou fixar versão espelhada | A imagem do Docker Hub não baixa mais | aberto |
| P2 | Docs (`docs/domain-language.md`, README raiz) | Atualizar o contexto "Platform": além de identidade, inclui educação, avaliação (leitura) e orquestração | Glossário desatualizado em relação ao Dossiê v3 | aberto |
| P3 | Raiz do monorepo (`pnpm-workspace.yaml`)  | Acrescentar em `allowBuilds`: `cpu-features: false`, `ssh2: false`, `protobufjs: false` | O pnpm 11 falha no `pnpm install --frozen-lockfile` quando há scripts de build sem decisão. Esses três vêm de dependências de desenvolvimento/observabilidade do `platform-api` (Testcontainers e exportador OTLP). `false` nega a execução dos scripts; nenhum deles é necessário (são binários opcionais) | **feito** (aprovado em 2026-11-18) |
| P4 | `ai-sim-service` | Confirmar ou ajustar o contrato interno proposto: `POST/GET /simulation/api/v1/planets[...]` e `/tutor/api/v1/{explain,hint,advisor,adaptation}` (ver `services/platform-api/src/modules/orchestration/infrastructure/adaptadores-http.ts`), autenticação com credencial de serviço do platform-api, SSE com `data: {"text": ...}`, 409 `/errors/insufficient-action-points` com `actionPoints`. Ser **autoritativo** sobre pontos de ação (`action_points`) e efeito das intervenções | O gateway só repassa; sem isso os fakes não podem ser substituídos | aberto |
| P5 | CI da raiz (`.github/workflows/`) — **precisa de aprovação** | Adicionar o job proposto em `services/platform-api/ci/platform-api.yml` (lint, tipos, contrato congelado, testes com Testcontainers e gate de cobertura, drift, auditoria de dependências, imagem) | O `ci-node.yml` atual roda só `lint build test` (sem integração nem contrato) | aguardando aprovação |
| P6 | `ai-sim-service` | Antes de coletar telemetria: consultar `GET /platform/api/v1/internal/consent/{userId}` com credencial de serviço; assinar `ConsentimentoRevogado` e `TitularExcluido` no stream `ecosfera.events.platform`; publicar `EvidenciaGerada`/`CompetenciaAtualizada` no stream `ecosfera.events.assessment` conforme `packages/api-contracts/asyncapi/platform-events.v1.yaml` | Gate de consentimento ponta a ponta (RF-071, RNF-009) | aberto |
| P7 | Infra (`infra/compose`) | Opcional: serviço Keycloak (ou Ory) de desenvolvimento e um LMS de teste (ex.: Moodle) para verificar OIDC/LTI 1.3 contra implementações reais; definir o host público do MinIO para URLs assinadas | Federação só foi verificada contra provedor local de teste | aberto |
| P8 | Frontend (`apps/web-client`) | Usar o OpenAPI/tipos de `packages/api-contracts`; refresh por cookie (`credentials: 'include'`); WebSocket com subprotocolos `['ecosfera.v1', 'bearer.<token>']` e reconexão com `?lastTickId=`; tratar `type=/errors/consent-required` com tela para o responsável | Contrato do cliente | aberto |
| P9 | Jurídico/DPO | Substituir os textos placeholder de `platform.consent_text` (versão `0.1-placeholder`), aprovar os prazos de `platform.retention_policy` e a base legal do inventário (`INVENTARIO_DE_DADOS.md`), e o k=5 do dataset | Bloqueio jurídico: não escrevemos texto legal | aberto |
| P10 | Pedagogia | Validar o catálogo BNCC semeado (28 habilidades, 10 competências, vínculos tema→competência, todos `pending_validation`) e os limiares de alerta | Bloqueio pedagógico (RSK-06) | aberto |
